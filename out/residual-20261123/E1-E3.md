**分段证据**：body_layout_probe.py 使用实际 fixture 的助手原文，走 parser→BodyDocument→attach。AST 是 11 个顶层块；有序列表 3 项、无序/任务合并列表 4 项，所有文本均在 attach 后文档中。两级引用、链接、alt 也存在。原始 18 vs 19 的额外带是 deva y602 的断图图标，alt 文本是 y606–619；QML 不是丢了某条列表/段落。

**行高和块间距证据**：
- 当前 deva app.css:765–789：正文 14px × 1.65=23.1px；li 上下 margin=2px；列表容器 bottom margin=12px。
- Qt 实测有序项 y331.609375→357.53125→383.453125，步长 25.921875；历史 deva DOM 每行约 23.09375+2=25.09375。每项约 0.828125px 的推进差随列表累积，不能只看名义 CSS 的 1.65。
- Qt 最后有序项 y383.453125 到第一无序项 y409.375，仍为 25.921875；deva 源码在两个列表之间应有列表容器 12px 段后距，历史 DOM ol y272.33/h73.28、ul y357.61 证实中间 12px。当前 `_list` 没有容器收尾间距，只逐个 `_list_item` 写 2px margin，确有块边界布局缺口。
- Qt 表格路径注释声称把 bottom 12px 放到后继块，但 `_after_frame` 只移动 cursor、设 _has_content，未给 _pending_top 赋值。表格后“要点”的偏移从表格带 −3..−5px 跳到 −20px，支持表后间距路径也需要修复，不是统一 scrollY 误差。
- Qt 引用用表格、margin=6px，和 deva 的 blockquote border-left/padding 布局机制不同。一级/二级引用差分别 −28/−21px，也不符合单一线性滚动偏移。

结论：E1 的“正文少行”被内容/AST/逐带映射排除；E3 仍是实际行推进、表格/列表边界、引用及视口裁切的混合布局差异。尚未实施这些布局修复，不能称已闭环。历史 DOM 只作与当前 CSS 相互印证的辅助证据，不冒充本轮 deva 运行值。
