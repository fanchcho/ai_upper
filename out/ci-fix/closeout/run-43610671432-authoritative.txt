## 3. arm64 失败的内层帧与 step

失败 step：**step 18 `Full integration run`**（其后 step 19 上传运行日志仍 success，
step 20/21 与 3 个 Post 步骤被 skip）。job 日志下载匿名不可得
（`GET /actions/jobs/132494820638/logs` → **HTTP 403** `Must have admin rights to Repository.`），
因此改用公开 check-run 注解（`GET /check-runs/132494820638/annotations` → HTTP 200，
12 条），其标题均为 `run.log (build.py --run exit 1)`，逐帧原文如下（由外到内）：

```
File "C:\a\ai_upper\ai_upper\dist\ai_upper\ai_upper.exe", line 4, in <module>

```

最内层失败帧：**`qt_compat.py:107` 的 `_QtModule.__init__`** → 它调用
`_binding_module()`，在 **`qt_compat.py:89`** 抛出
`ImportError: <binding> has no submodule '<submodule>': <原始 ImportError>`；
该异常在 `web_shell_window.py:136` 被重新包装成
「该 binding 没有 QtWebEngine，无法承载渲染层：…」后继续上抛，最终
`build.py --run` 以 exit 1 结束。注解另有 `failure  Process completed with exit code 1.`
同 job 的 `pytest (exit 0)`：`978 passed, 16 skipped in 65.28s` —— 单测层是绿的，
红点只在 `[6/6]` 的打包产物启动。

根因不变且已判定：PySide6 的 win_arm64 wheel 不含 `Qt6WebEngineCore`
（arm64 addons wheel 里 `Qt6WebEngine*` 条目为 0），属上游不发轮子，不是本仓库
3.8 兼容问题。矩阵条目保留、不加 skip、`requires-python` 未放宽。
