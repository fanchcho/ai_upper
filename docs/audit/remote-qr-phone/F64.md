# F64 手机链路增量：本地真实往返闭环，真手机及公网未验证

原版依据（均只读）：
- `deva/apps/desktop/src/main/services/remote/web/phone.ts:32-36` 默认端口 17800、通道延长 30 秒、收起 QR 后 5 秒关闭；`:199-220` QR/link hold；`:322-463` 添加、移除、启停、重试、二维码/链接、设备撤销；`:467` 在线/离线、via、lastSeen 状态。

- `remote/web/adapter.ts:175-295` hello / refresh / history / send / new / stop 与设备身份；`shared/remote-web.ts:213-298` 会话帧格式。

实现：
- `app/src/mvvm/services/phone_lan.py` 同端口 HTTP 静态页与 `/ws`，监听 LAN；只允许固定静态资源，无目录暴露。
- `phone_relay.py` Qt WebSocket 主动外连，原版信封和心跳/重连；公网强制 TLS，本地 127.0.0.1 HTTP 可复现。
- `web_pairing.py` 复用既有 X25519/HKDF/ChaCha20-Poly1305、一次票据、顺序校验；LAN/relay 使用同一个加密门；设备密钥写 vault，在线/离线及最后活动写配置，撤销断开当前连接；有设备或有效票据时保留相应通道，启动后按已保存设备恢复。
- `phone_sessions.py` 新建/列表/历史/发送/停止接真实 ChatHost 与 ChatSessionStore，沿用 scope，拒绝越权 sid 与非法新 sid；不使用替身回调。
- `qml/PhonePane.qml` 真实 QR、复制链接、两通道状态、启停/删除、设备撤销。`web_pair/client.ts` 手机页面真实浏览器输入、发送、历史、新建、密钥续连。

脚本真实点击 QML 生成 LAN/relay 二维码；真实 Electron 浏览器页面完成加密配对、鼠标点击新建、文本输入、点击发送；本机 HTTP 模型 fixture 接收真实主回合请求，返回 `LOCAL_MODEL_REPLY`，生产 ChatHost 落盘并从连接发回；页面刷新用设备密钥恢复（不重复建设备）；新建 ChatSessionStore 重新读盘验证用户/助手正文；真实 QML 点击撤销，浏览器断开，重新读 config/vault 确认设备与 key 删除。另有真实点击取消 QR 后票据消失、复制一次性链接后取消 QR 不撤销 sticky 票据及剪贴板读回。暗亮各 LAN/relay 四组，见 phone-readback.json、phone-ui.log、phone-{qr,device,browser}-{dark,light}-{lan,relay}.png。

证据边界：relay 与模型端点都是明确标注的 127.0.0.1 fixture。4 次真实 HTTP 模型请求、加密 relay 信封、会话文件读回都保存。**不是实际手机、不是公网 relay、不是外部模型成功证明**；无真实手机扫码、真实 LAN 第二设备、公网跨网/移动网络、浏览器外部推送仍未验证。

本轮指定的 QR→LAN/relay→文字主会话往返→设备撤销已在本机闭环。完整原版手机应用的附件上传/交付文件下载、计划/权限卡片交互、任务管理、安装到主屏幕票据等扩展帧 **未完成**（phone_sessions.handle 当前只消费文字会话核心帧）；不能把本机核心链路当成整个原版手机应用全部移植。
